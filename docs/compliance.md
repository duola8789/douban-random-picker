# 法律与平台风险说明

> 本文是工程视角的风险梳理，**不构成法律意见**。涉及具体判断时请咨询律师。

写给两个读者：一是作者自己（决定要不要发布、怎么发布），二是将来想 fork 的人（知道边界在哪）。

## 一、这个扩展在技术上做了什么

客观描述，不带评价：

1. 在用户已登录的豆瓣页面内，用页面自己的会话发起 HTTP GET 请求；
2. 请求的地址是豆瓣移动端网页内部使用的 JSON 接口（`m.douban.com/rexxar/api/v2/...`），**未在任何公开文档中发布**；
3. 按 1200ms 间隔串行分页，只读，不写入；
4. 数据只写入用户本机的 `chrome.storage.local`，不上传；
5. 请求频率受 24 小时缓存与 10 分钟最短更新间隔双重限制。

## 二、与豆瓣用户协议的关系

豆瓣的用户协议通常包含「不得使用自动化程序抓取本站内容」一类的条款。本扩展的行为落在这条边界附近，风险大小与**分发范围**强相关：

| 使用方式 | 风险等级 | 说明 |
|---|---|---|
| 自己用，不公开 | 低 | 规模等同于一个人多刷几次网页 |
| 开源发布，用户自行加载 | 中 | 请求总量随用户数增长，可能触发风控或限流 |
| 上架 Chrome Web Store | 中高 | 公开分发 + 可被搜索，暴露面最大 |

需要如实承认的一点：**公开分发会直接提高接口被封堵的概率**。这既是平台风险，也是产品风险——如果接口被关闭，扩展就失效了。

缓解措施（已实现）：

- 只读，不写入任何数据；
- 串行请求，1200ms 间隔；
- 24 小时缓存 + 10 分钟最短更新（手动同步也不能突破）；
- 遇到 429 立即停止；
- 不伪装 User-Agent，不绕过任何验证码或风控。

## 三、《个人信息保护法》角度

本扩展只在**用户自己的设备上**、处理**用户自己**的数据，不向任何第三方提供、不跨境传输、不做画像。因此：

- 不构成「个人信息处理者向第三方提供个人信息」；
- 不涉及数据出境；
- 不需要单独同意流程。

但要注意：**如果将来加了任何形式的云端同步或统计，这条判断就立刻不成立**，需要重新评估并改写隐私政策。

## 四、商标与名称

- 「豆瓣」是豆瓣（北京豆网科技有限公司）的商标。在扩展名称与描述中使用它，属于描述兼容对象的**描述性使用**，但必须在显著位置说明「非官方」。
- **不要**使用豆瓣的 logo、豆瓣的绿色品牌色作为主视觉，也不要让图标看起来像豆瓣官方产品。
- 本扩展的图标是自绘的骰子图案，与豆瓣标识无关，这条是安全的。
- 商店描述中不得出现「官方」「推荐」「合作」等暗示授权的措辞。

## 五、Chrome Web Store 政策

需要逐条对上的若干项：

| 政策项 | 本扩展的情况 | 结论 |
|---|---|---|
| Single Purpose（单一用途） | 只做「从收藏里随机抽一个」 | 符合 |
| 权限最小化 | 仅 `storage`、`sidePanel` + 豆瓣域名 | 符合 |
| 隐私政策 | 已提供 `PRIVACY.md`，需一个公开可访问的 URL | 待办 |
| 用户数据披露 | 商店后台的「数据使用」表单需声明不收集 | 待办 |
| 不得误导 | 描述中须写明「非官方」 | 待办 |
| 远程代码 | 没有远程加载任何脚本 | 符合 |

**最可能卡住的一环**：审核员看到扩展抓取第三方网站的未公开接口，可能要求解释或直接驳回。应对方式是主动在描述里说清楚：只读、只访问用户自己的数据、有频率限制、不写入、无服务器。

## 六、风险清单与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| 豆瓣接口变更或下线 | 扩展功能失效 | 保留错误提示；`ROADMAP.md` 已记录 HTML 解析与快照导入两条兜底路径 |
| 用户被限流或 IP 被封 | 无法同步 | 缓存 + 最短更新间隔 + 429 立即停止 |
| 收到豆瓣方的下架/删除要求 | 需停止分发 | 尊重对方要求；本项目无服务器，下架即彻底停止 |
| 用户误以为是豆瓣官方产品 | 商标风险 | 名称与描述明示「非官方」，图标自绘 |
| 商店审核驳回 | 无法上架 | 权限用途逐条说明，主动披露只读与技术实现 |

停止公开分发（下架、设为私有）即可。本项目没有服务器、没有用户数据库，不存在需要清理的服务端数据；已安装用户的数据全部在他们自己的浏览器里，扩展停止运行即停止请求。
