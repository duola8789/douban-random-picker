## Why

v1 的候选只有「想看 / 想读」，看过的片子永远抽不到——想重温时无从下手。另一边，池子里总有一些条目是用户明确不想抽的，唯一的手段是抽到它再跳过，而跳过每天只有 2 次；池子越大，这个手段越不够用。

这两件事合起来说明：候选池需要「进得来」也需要「管得住」。再加上历史只增不减、找一条记录要翻很久，以及窄侧边栏下封面留白，v2 剩下的四块功能一起做，比拆成四个 change 更省事——它们共享同一套候选池过滤逻辑。

## What Changes

- **候选来源扩展到「看过 / 读过」**：同步新增 `movie:done`、`book:done` 两个维度；抽取池改为 `mark ∪ done` 的大池子，不分来源、不分意图；卡片对 `done` 条目打「重温」标签。
- **新增候选池页**（独立标签页，与记录页并列）：
  - 电影 / 剧集 / 图书三个页签，列出同步下来的全部候选。
  - 每行展示标题、标记时间、我的评论（有才显示）、来源标签。
  - 筛选：来源（想看 / 看过）、标记时间范围、是否有我的评论。
  - 单条屏蔽、多选批量删除、按来源批量删除。
  - 「已屏蔽」视图，可恢复。
  - 侧边栏提供入口。
- **本地屏蔽即删除**：扩展不写豆瓣，所以「删除」只记在本地 `hidden` 集合里；抽取与候选池页都据此过滤。屏蔽是条目级、全局的；屏蔽正在待看的那条会被拒绝——否则它就成了重新抽取的后门。
- **历史增强**：记录页支持按类别与来源筛选，支持导出为 JSON 文件。
- **窄侧边栏封面适配**：竖排时封面不再左边贴齐、右侧空一块，改为居中并在一档内缩放。
- 明确不做：片单 / 书单 / 官方榜单 / 公开列表来源（接口已调研，结论留在 ROADMAP）；任何豆瓣写操作。

## Capabilities

### New Capabilities

- `candidate-list`: 以独立页面呈现同步下来的候选条目，支持筛选、单条屏蔽、批量屏蔽、查看与恢复已屏蔽条目，并让这些操作反映到抽取池。

### Modified Capabilities

- `interest-sync`: 同步维度从「想看 / 想读」扩展到同时覆盖「看过 / 读过」，请求量与并发策略随之变化；新鲜期与最短更新频率对新增维度同样生效。
- `random-pick`: 候选池改为 `mark ∪ done` 的合并池；卡片为 `done` 条目打「重温」标签；抽取时排除本地屏蔽的条目；窄侧边栏下封面居中。
- `draw-history`: 记录页新增按类别 / 来源筛选与导出；与候选池页的「屏蔽」保持两套数据，互不替代。

## Impact

- **代码**：`src/lib/cache.js`（维度定义）、`src/background/sync.js`（按维度下发 status）、`src/background/storage.js`（hidden 存储）、`src/background/service-worker.js`（屏蔽相关消息、计数合并）、`src/lib/picker.js`（合并池与屏蔽过滤）、`src/lib/labels.js`（重温标签）、`src/sidepanel/`（入口与封面）、新增 `src/candidates/`、`src/history/`（筛选与导出）。
- **存储**：新增 `hidden: { [key]: removedAt }`；`caches` 新增两个 done 维度。
- **网络**：一次完整同步从 2 个维度变为 4 个，请求总量约翻倍。沿用现有的串行分页、1200ms 间隔与最短更新频率，不做额外加压。
- **接口**：不新增豆瓣端点，不写入豆瓣。`status=done` 早已实测可用。
- **版本**：minor。新增「重温」与「候选池页」两个能独立说出的能力。
- **风险**：屏蔽完全依赖本地记录，换浏览器或清空存储后失效；这一点要在帮助内容与候选池页里说清楚。记录上限与 hidden 的清理关系也需要定（见 design）。
